# 🛡️ NIDS — Network Intrusion Detection System

A real-world, production-ready Network Intrusion Detection System built with Python, Scapy, scikit-learn, Flask, and SQLite.

---

## 🏗️ Architecture

```
nids_project/
├── config/
│   ├── main.py                  # Orchestration entry point
│   ├── cli.py                   # Full CLI (start/stop/configure/events/dashboard)
│   ├── packet_capture.py        # Scapy-based packet capture (BPF filter, live/batch)
│   ├── signature_detection.py   # Stateful rule engine (protocol, flags, ports, time window)
│   ├── anomaly_detection.py     # ML-based detection (IsolationForest, 10 network features)
│   ├── logging_alerting.py      # Structured logging (file + console, severity levels, colour)
│   ├── database.py              # SQLite persistence (events, stats, top sources)
│   ├── notifications.py         # Email + Slack alerting (rate-limited, background threads)
│   ├── dashboard.py             # Flask web dashboard (SSE live feed, Chart.js, dark theme)
│   ├── rules.json               # Signature detection rules (editable)
│   ├── anomaly_thresholds.json  # Anomaly thresholds (editable)
│   ├── notification_config.json # Email / Slack credentials (editable)
│   └── requirements.txt
├── models/
│   ├── train_model.py           # Trains IsolationForest on synthetic network traffic
│   ├── anomaly_model.joblib     # Trained model (generated by train_model.py)
│   └── anomaly_detection_data.csv
├── logs/
│   ├── nids.log                 # Structured log file (auto-created)
│   └── nids.db                  # SQLite database (auto-created)
└── dataset.py                   # Utility: generate sensor anomaly dataset
```

## ⚡ Quick Start

### 1. Install dependencies
```bash
pip3 install -r config/requirements.txt
```

### 2. Train the anomaly detection model
```bash
python3 models/train_model.py
```
This generates synthetic network traffic (normal + SYN flood, UDP flood, ICMP flood, port scan), trains an IsolationForest, and saves `models/anomaly_model.joblib`.

### 3. Run the NIDS

**Batch mode** (capture N packets, then analyse):
```bash
sudo python3 config/main.py
```

**Live real-time mode** (analyse each packet as it arrives):
```bash
sudo python3 config/main.py --live
```

**With web dashboard**:
```bash
sudo python3 config/main.py --live --dashboard
# Then open: http://localhost:5000
```

**Specific interface + BPF filter**:
```bash
sudo python3 config/main.py -i eth0 --live --filter "not arp" --dashboard
```

## 🖥️ CLI Reference

```bash
python3 config/cli.py [COMMAND] [OPTIONS]
```

| Command | Description |
|---------|-------------|
| `start` | Start the NIDS (capture + detect) |
| `stop` | Stop a running NIDS process |
| `configure` | Show current configuration |
| `interfaces` | List available network interfaces |
| `dashboard` | Launch the web dashboard only (reads existing DB) |
| `events` | Print recent intrusion events from the DB |

### Examples
```bash
# Start with dashboard on port 8080, live mode, only TCP traffic
sudo python3 config/cli.py start -i eth0 --live --dashboard --dashboard-port 8080 -f tcp

# Show last 50 critical events
python3 config/cli.py events --limit 50 --severity CRITICAL

# Launch dashboard standalone (no capture)
python3 config/cli.py dashboard --port 5000

# Check config
python3 config/cli.py configure

# List interfaces
python3 config/cli.py interfaces
```

## 🌐 Web Dashboard

Open **http://localhost:5000** after starting with `--dashboard`.

Features:
- **Live event feed** via Server-Sent Events (SSE) — zero polling, instant updates
- **Stats cards** — total events, last 24 h, per-severity counts
- **Timeline chart** — events per hour over the last 24 hours (Chart.js)
- **Top attacker IPs** — bar chart of most active source IPs
- **Paginated event log** — filterable by severity
- **Dark theme** — easy on the eyes during long monitoring sessions

## 🔔 Notifications (Email & Slack)

Edit `config/notification_config.json` to configure alerts for **HIGH** and **CRITICAL** events:

```json
{
  "email": {
    "enabled": true,
    "host": "smtp.gmail.com",
    "port": 587,
    "user": "your@gmail.com",
    "password": "your_app_password",
    "from": "your@gmail.com",
    "to": "alerts@yourdomain.com"
  },
  "slack": {
    "enabled": true,
    "webhook": "https://hooks.slack.com/services/YOUR/WEBHOOK/URL"
  }
}
```

Or use environment variables:
```bash
export NIDS_EMAIL_ENABLED=true
export NIDS_EMAIL_USER=your@gmail.com
export NIDS_EMAIL_PASSWORD=yourpassword
export NIDS_EMAIL_TO=alerts@yourdomain.com
export NIDS_SLACK_ENABLED=true
export NIDS_SLACK_WEBHOOK=https://hooks.slack.com/services/...
```

> **Gmail tip**: Use an [App Password](https://support.google.com/accounts/answer/185833) — not your regular password.

Notifications are **rate-limited** (max 1 per 5 minutes per unique alert) to avoid flooding.

## 🗄️ Database

All events are persisted to `logs/nids.db` (SQLite, auto-created).

Schema:
- `intrusion_events` — all signature and anomaly detections with full metadata
- `system_events` — NIDS startup, shutdown, and batch summary events

Query directly:
```bash
sqlite3 logs/nids.db "SELECT timestamp, severity, src_ip, description FROM intrusion_events ORDER BY timestamp DESC LIMIT 20;"
```

Or use the CLI:
```bash
python3 config/cli.py events --limit 20 --severity HIGH
```

## 📋 Signature Rules

Edit `config/rules.json` to add or tune detection rules:

```json
{
  "id": 7,
  "description": "DNS Amplification Attack",
  "protocol": "udp",
  "src_ip": "any",
  "dst_ip": "any",
  "src_port": "any",
  "dst_port": 53,
  "threshold": 30,
  "time_window": 10
}
```

**Rule fields:**

| Field | Description |
|-------|-------------|
| `protocol` | `tcp`, `udp`, `icmp`, or `any` |
| `src_ip` / `dst_ip` | IP address or `any` |
| `src_port` / `dst_port` | Port number or `any` |
| `flags` | TCP flags: `SYN`, `ACK`, `FIN`, `RST`, `PSH`, `URG` (comma-separated) |
| `type` | ICMP type: `echo-request` or `echo-reply` |
| `threshold` | Number of matching packets to trigger alert |
| `time_window` | Sliding time window in seconds |

## 🤖 ML Anomaly Detection

The model is trained on 10 real network features extracted from each packet:

| Feature | Description |
|---------|-------------|
| `packet_length` | Total packet size in bytes |
| `protocol` | IP protocol (6=TCP, 17=UDP, 1=ICMP) |
| `src_port` | Source port |
| `dst_port` | Destination port |
| `tcp_flags` | TCP flags as integer |
| `icmp_type` | ICMP type field |
| `payload_length` | Transport-layer payload size |
| `is_fragmented` | 1 if IP fragment, else 0 |
| `ttl` | IP Time-To-Live |
| `header_length` | IP header length |

Attack patterns used in training: **SYN flood**, **UDP flood**, **ICMP flood**, **Port scan**.

## 🔧 Troubleshooting

| Problem | Solution |
|---------|----------|
| `PermissionError` on capture | Run with `sudo` (Linux/macOS) or as Administrator (Windows) |
| `Interface not found` | Run `python3 config/cli.py interfaces` to list valid names |
| `Model file not found` | Run `python3 models/train_model.py` first |
| `No module named flask` | Run `pip3 install -r config/requirements.txt` |
| Dashboard not loading | Check port 5000 is free; use `--dashboard-port 8080` |
| No packets captured | Check interface name; try `--filter ""` to capture all traffic |
